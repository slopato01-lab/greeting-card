# Как поставить это в папку Greeting-cards

## 1. Сделать резервную копию

Один раз, чтобы можно было вернуться:

```bash
cd путь/до/Greeting-cards
git add -A && git commit -m "снимок перед заменой документации"
```

Если там ещё нет git — просто скопируй папку рядом:

```bash
cp -r Greeting-cards Greeting-cards-backup
```

## 2. Что удалить

Удаляй только документацию и старые макеты. **Код, если он там уже
есть, не трогай** — новые правила написаны так, чтобы лечь на него.

```bash
cd путь/до/Greeting-cards
rm -f CLAUDE.md START-HERE.md README-docs.md
rm -rf docs design .claude/commands
```

## 3. Что положить

Распакуй архив и скопируй содержимое в корень папки:

```
Greeting-cards/
├─ CLAUDE.md              ← правила, Claude Code читает автоматически
├─ START-HERE.md          ← этот файл
├─ docs/
│  ├─ DESIGN.md           ← токены из твоего макета
│  ├─ FIGMA.md            ← карта фреймов, ассеты, что править
│  ├─ PRODUCT.md          ← продукт и все тексты интерфейса
│  ├─ SECURITY.md         ← требования безопасности
│  └─ TESTING.md          ← чек-листы и матрица устройств
├─ design/
│  ├─ desktop.html        ← эталон 1920, node 324:246
│  └─ mobile.html         ← эталон 390, node 341:607
└─ .claude/commands/      ← /new-screen, /new-game, /review
```

## 4. Проверить, что Claude Code это увидел

Запусти в папке и спроси:

> Прочитай CLAUDE.md и docs/. Перескажи своими словами: какие точки
> перелома у проекта, откуда берутся цвета и тексты, и что нельзя
> делать без моего согласия. Ничего не меняй.

Если пересказ совпадает с документами — вводные приняты.

# Первые запросы

Строго по порядку, каждый следующий после проверки предыдущего.

**1. Каркас**

> Создай каркас: Next.js на Cloudflare Workers, TypeScript strict,
> Tailwind, pnpm. Линтер, форматтер, GitHub Actions с проверкой типов.
> `.env.example` с именами переменных без значений. Ни одной страницы,
> ни одного компонента. Сначала покажи план.

**2. Токены в код**

> Перенеси токены из docs/DESIGN.md в конфиг Tailwind и CSS-переменные.
> Подключи Montserrat Alternates (400,500,600,700) и Inter (400,500)
> с кириллицей и display: swap. Сделай страницу /styleguide со всей
> типографической шкалой, цветами, радиусами, тенями и тремя
> состояниями кнопки и пилюли — мне нужно смотреть систему с телефона.

**3. Словарь текстов**

> Собери словарь из docs/PRODUCT.md в типизированный модуль i18n:
> ключ → строка, русский. Тип запрещает обращение к несуществующему
> ключу. Опечатки из docs/FIGMA.md уже исправь.

**4. Ассеты**

> По списку в docs/FIGMA.md скачай иконки из Iconify в public/assets/
> и сделай компонент Icon, который их отдаёт. Ссылки на figma.com
> в design/*.html не использовать — они временные.

**5. Первая секция**

> Свёрстай шапку и герой главной страницы. База — design/mobile.html,
> десктопная раскладка из design/desktop.html от 1280px. Поток, не
> абсолютное позиционирование. Покажи план, потом код, потом сверку
> с эталоном на 390 и 1920.

Дальше — секция за секцией, снизу списка в `docs/FIGMA.md`.

# Что делать в первую очередь руками, без кода

1. **Проверить приём платежа** через bePaid на минимальную сумму.
   Это может обнулить часть архитектуры, лучше узнать сейчас.
2. **Переписать черновые тексты** из таблицы в `docs/FIGMA.md` —
   восемь карточек шаблонов с одинаковой подписью и три одинаковых
   описания преимуществ бросаются в глаза сразу.
3. **Дорисовать состояния кнопок** — hover, нажатие, фокус, выключено.
   Их нет в макете, а без них вёрстка будет придумана за тебя.
4. **Решить, что внутри карточек шаблонов** — сейчас это пустые
   прямоугольники, а это главный товар на странице.
