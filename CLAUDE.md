# Открыточка — правила работы в репозитории

Платформа персонализированных интерактивных открыток.
Открытка = игра + тема + фото пользователя + тексты + сюрприз в финале.

Рынок: Беларусь и Россия. Язык интерфейса: русский. Валюта: BYN и RUB.
Работает один человек. Значит: простые решения побеждают умные.

## Читать перед работой

| Файл | Когда открывать |
|---|---|
| `docs/DESIGN.md` | любая задача с визуалом. **Источник правды по токенам** |
| `docs/FIGMA.md` | сборка страницы из макета, работа с ассетами |
| `docs/PRODUCT.md` | нужен любой текст интерфейса |
| `docs/SECURITY.md` | загрузки, оплата, доступ к данным, секреты |
| `docs/TESTING.md` | перед тем, как сказать «готово» |
| `design/mobile.html` | эталон мобильной раскладки, node `341:607` |
| `design/desktop.html` | эталон десктопной раскладки, node `324:246` |

Значения цветов, размеров и радиусов берутся из `DESIGN.md`.
Придумывать свои — нельзя.

## Как отвечать

1. **Сначала план**: список файлов, что в каждом меняется, риски.
   Дождись подтверждения. Код в том же сообщении не пиши.
2. Потом код — целиком, без `TODO` и без «здесь будет логика».
3. Потом проверки: типы, сборка, чек-лист из `TESTING.md`.
4. Отчёт: что сделано, что не сделано, что проверить руками.

Одна задача — один разговор. Одна ветка на задачу.

## Работа с макетом

- **Мобильный первым.** База — `design/mobile.html`, 390px.
  Десктопная раскладка включается медиазапросом от 1280px.
- **Абсолютные координаты из эталонов в продакшн не переносятся.**
  Эталоны сверстаны абсолютом, потому что во фрейме нет Auto Layout.
  В коде секции идут потоком, координаты нужны только для проверки
  порядка и вертикальных отступов.
- **Фиксированные высоты становятся минимальными.** Текст на русском
  длиннее макетного, имена бывают в три слова.
- Три ряда на мобильном — горизонтальные карусели, см. `DESIGN.md`.
  Не превращать их в сетку и не обрезать содержимое.
- Промежуток 768–1279 в макете не нарисован. Туда идёт мобильная
  раскладка с увеличенными полями, пока не появятся планшетные фреймы.

## Жёсткие правила

**Вёрстка**
- Ни одного цвета, шрифта, радиуса или тени в явном виде — только
  переменные из `DESIGN.md`.
- Ни одной строки, видимой пользователю, в коде — только ключи
  из словаря `docs/PRODUCT.md`.
- Область нажатия минимум 44×44. Пилюли фильтров в макете 33px —
  добавлять невидимую зону нажатия.
- Каждое интерактивное состояние существует: обычное, наведение,
  нажатие, фокус, выключено, загрузка, ошибка, пусто. В макете их нет —
  проектируются от токенов и согласуются.
- Обводки только 1px и 2px. Дробные значения из макета — артефакт
  масштабирования фрейма.

**Код**
- TypeScript strict. Ни одного `any`, ни одного `!` для подавления типа.
- Валидация входных данных на границе каждого API-роута.
- Никаких новых зависимостей без согласования.
- Всё, что подписалось, отписывается по `AbortSignal`.
- `Math.random()` в игре запрещён — только seeded-генератор от slug
  открытки: она обязана раскладываться одинаково при каждом открытии.

**Данные и деньги**
- Открытка создаётся по вебхуку оплаты, а не по возврату пользователя
  на сайт. Он закроет вкладку.
- Обработчик вебхука идемпотентен: платёжка пришлёт событие дважды.
- Секреты только в переменных окружения. Ключи ИИ-сервисов и платёжки
  вызываются только с сервера.
- Черновик сохраняется каждые 3 секунды локально и на сервере.

## Определение готовности

- [ ] `pnpm typecheck` и `pnpm lint` без ошибок
- [ ] Проверено на 360 / 390 / 430 / 768 / 1280 / 1920
- [ ] Сверено с эталоном из `design/` в браузере, окно в окно
- [ ] Карусели прокручиваются пальцем, последняя карточка не липнет к краю
- [ ] Работает при `prefers-reduced-motion: reduce`
- [ ] Клавиатурная навигация, видимый фокус, контраст текста ≥ 4.5:1
- [ ] Есть состояния загрузки, ошибки и пустоты
- [ ] Нет утечек: слушатели, таймеры, rAF сняты
- [ ] Соответствующий пункт `SECURITY.md` соблюдён
- [ ] Тексты взяты из словаря

## Стоп-слова

Останови работу и спроси, если задача требует:
- изменить контракт игрового модуля
- добавить зависимость
- изменить схему БД
- поменять что-то в оплате
- отступить от `DESIGN.md`
- придумать текст, которого нет в словаре
- дорисовать раскладку, которой нет в макете

## Чего не делать никогда

- Не полировать визуал, пока функция не работает end-to-end.
- Не тащить временные ссылки на ассеты Figma в продакшн — они
  умирают через неделю, см. `docs/FIGMA.md`.
- Не хранить данные карт. Только редирект или виджет платёжки.
- Не логировать содержимое сообщений пользователей и URL их фото.
- Не говорить «готово» без прогона по чек-листу.
