# Тестирование

Один человек не может тестировать всё вручную каждый раз. Поэтому:
критичное — автотестами, визуал — по чек-листу, устройства — раз в неделю.

## Матрица устройств

Минимум, без которого не запускаемся:

| Устройство | Почему именно оно |
|---|---|
| iPhone, Safari, не последней модели | Самые строгие ограничения: звук, `100vh`, приватный режим |
| Android бюджетный, Chrome | Самый медленный. Здесь ломается анимация |
| **Встроенный браузер Telegram** | Основной сценарий получателя. Ломается чаще всего |
| Встроенный браузер Instagram | То же самое, другие ограничения |
| Десктоп Chrome | Часть дарителей делает открытку с компьютера |

Эмулятор в DevTools не заменяет телефон. Он не воспроизводит ни задержку
касания, ни реальную производительность, ни поведение встроенных браузеров.

## Известные ловушки мобильных браузеров

- `100vh` в Safari не равен видимой высоте — адресная строка съедает часть.
  Использовать `100dvh` с запасным вариантом.
- Звук не играет до первого касания. Первое касание — кнопка «Начать».
- В приватном режиме Safari часть хранилищ недоступна. Черновик должен
  переживать это без падения.
- Встроенный браузер Telegram может не поддерживать часть современных API.
  Проверять наличие метода перед вызовом, а не полагаться на версию.
- Клавиатура на мобильном перекрывает поле ввода. Прокручивать к полю.
- Поворот экрана посреди игры не должен сбрасывать прогресс.
- Долгое нажатие вызывает выделение текста и меню. Отключать там, где мешает.
- `touch-action: none` обязателен на игровых поверхностях, иначе страница
  скроллится вместо игры.

## Автотесты

**Обязательно покрыть:**
- Сквозной сценарий: создал открытку → оплатил в тестовом режиме →
  открыл ссылку → прошёл игру → увидел сюрприз.
- Вебхук оплаты: дубликат события не создаёт вторую открытку.
- Генерация slug: нет коллизий на миллионе значений.
- Доступ к чужой открытке по подобранной ссылке невозможен.
- Нормализация конфига игры: битые данные не роняют плеер.

**Скриншот-тесты:** каждая игра во всех четырёх темах на 390px.
Ловят регресс визуала, который глазами не заметишь.

## Чек-лист любого экрана

- [ ] 360 / 390 / 430 / 768 px
- [ ] Все четыре темы
- [ ] Состояния: загрузка, ошибка, пусто, успех
- [ ] Клавиатура: Tab проходит везде, фокус виден
- [ ] `prefers-reduced-motion: reduce`
- [ ] Медленная сеть (Slow 4G в DevTools)
- [ ] Длинный текст и пустой текст
- [ ] Контраст текста ≥ 4.5:1

## Чек-лист конструктора

- [ ] Черновик восстановился после закрытия вкладки
- [ ] Черновик восстановился после разряженного телефона
- [ ] Загрузка 10 фото на медленной сети: виден прогресс, можно продолжать
- [ ] HEIC с iPhone показывается корректно
- [ ] Повёрнутое фото встало правильно
- [ ] Превью совпадает с тем, что увидит получатель
- [ ] Можно пройти весь путь одной рукой, не поворачивая телефон

## Чек-лист игры

- [ ] Минимальное и максимальное число фото по манифесту
- [ ] Одинаковая раскладка при повторном открытии
- [ ] 60 fps на бюджетном Android при 4-кратном замедлении процессора
- [ ] Работает при выключенном звуке
- [ ] Экран заблокировался и разблокировался — игра продолжается
- [ ] Поворот экрана не сбрасывает прогресс
- [ ] `destroy()` не оставил слушателей, таймеров и rAF

## Чек-лист оплаты

- [ ] Реальный платёж на минимальную сумму прошёл
- [ ] Пользователь закрыл вкладку сразу после оплаты — открытка создалась
- [ ] Дубликат вебхука обработан один раз
- [ ] Неуспешная оплата: понятное сообщение, черновик цел
- [ ] Возврат средств проходит по описанной в оферте процедуре

## Ритм

- **Каждая задача** — чек-лист экрана.
- **Каждая пятница** — прогон на реальных устройствах из матрицы.
- **Перед релизом** — полный прогон всех чек-листов плюс
  `docs/SECURITY.md` построчно.
