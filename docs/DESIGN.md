# Дизайн-система «Открыточка»

Источник правды по визуалу. Все значения взяты из макетов Figma
(десктоп `324:246`, мобильный `341:607`) и округлены до целых.
Эталонная вёрстка лежит в `design/desktop.html` и `design/mobile.html`.

Если задача требует отступить от документа — сначала меняется документ.

## Характер

Плотный, контрастный, «печатный». Чёрные обводки, крупная типографика,
розовый как единственный акцент, светло-розовые заливки секций.
Ничего полупрозрачного, никаких размытий и градиентов, кроме тех,
что явно заданы ниже.

Правило: **акцент один — розовый `#c9356f`.** Он маркирует действие
(кнопка, активный фильтр) и подложку главного заголовка. Больше нигде.

## Шрифты

Оба с полной кириллицей и свободной лицензией — проверено.

```css
--font-display: 'Montserrat Alternates';  /* 400, 500, 600, 700 */
--font-ui:      'Inter';                  /* 400, 500 */
```

Montserrat Alternates — заголовки, карточки, навигация подвала, всё
«характерное». Inter — кнопки, навигация шапки, вводный абзац героя,
служебные подписи в плашках шаблонов.

Трекинг во всём макете равен 1% кегля. В коде это одна строка
`letter-spacing: 0.01em`, а не дробные пиксели в каждом правиле.

## Цвет

```css
--pink:        #c9356f;  /* акцент: кнопки, активные фильтры, подложка H1 */
--pink-tint:   #ff3d89;  /* только с opacity 0.1 — заливка секций */
--pink-card:   #ffecf3;  /* фон карточек внутри розовых секций */
--dark:        #2d2b32;  /* тёмные блоки: CTA и подвал */
--dark-badge:  #23202b;  /* номерные квадраты этапов */
--ink:         #000000;  /* текст и все обводки */
--nav:         #3a3a3a;  /* навигация в шапке (десктоп) */
--btn-ghost:   #363636;  /* текст вторичной кнопки (мобильный) */
--muted:       #7a7a7a;  /* второстепенный текст, обводки неактивных пилюль */
--muted-2:     #6c6c6c;  /* неактивные пилюли фильтров (десктоп) */
--body:        #5c5c5c;  /* тело текста в карточках */
--caption:     #5a5a5a;  /* подписи, чек-строки */
--photo:       #909090;  /* плейсхолдер изображения в карточке */
--white:       #ffffff;
```

Мобильный H1 использует интерлиньяж 1.1, а не 1.15 — иначе пять строк
не помещаются в первый экран. Это не опечатка, так в макете.

Первых трёх ролей в исходной таблице не было: значения сняты с макетов
при вёрстке шапки и героя.

**Размер и цвет делят одно пространство имён.** Если есть `--text-foo`
и `--color-foo`, утилита `text-foo` отдаёт цвет, а размер молча
пропадает — ошибка не всплывает ни в типах, ни в сборке, текст просто
рендерится не тем кеглем. Поэтому у ролей, рядом с которыми живёт
одноимённый цвет, размер назван иначе:

| Размер | Почему не очевидное имя |
|---|---|
| `--text-menu` | рядом `--color-nav` |
| `--text-sub` | рядом `--color-body` |
| `--text-note` | рядом `--color-caption` |
| `--text-card` | утилита `text-base` встроена в Tailwind |

Найдено 03.08.2026 после вёрстки лендинга: `text-body` и `text-caption`
стояли в пяти местах как размер, а отдавали цвет. Заодно перепутанными
оказались десктопные кегли подписи подвала, пунктов списка в карточке
FAQ и подписи CTA. Проверять такое нужно в собранном CSS: `.text-body`
там должен быть `font-size`, а не `color`. Выделенные строки H1 — SemiBold на мобильном
и Bold на десктопе, так нарисовано в обоих фреймах.

Розовая подложка H1 обнимает текст, а не повторяет прямоугольник
из макета: в потоке она живёт на строчном элементе и выступает
на 7px (мобильный) и 12px (десктоп) за края текста, как в макете.
Каждая перенесённая строка получает свой прямоугольник — за это
отвечает `box-decoration-break: clone`.

## Геометрия

```css
/* Радиусы — берутся из макета как есть, не унифицировать */
5px   — розовая подложка H1 (мобильный)
3px   — платёжная плашка в подвале (мобильный)
4px   — платёжная плашка в подвале (десктоп)
7px   — номерной квадрат этапа (мобильный)
8px   — номерной квадрат этапа (десктоп)
18px  — карточка преимущества (мобильный)
9px   — розовая подложка H1 (десктоп)
10px  — кнопка (мобильный)
12px  — кнопка шапки (десктоп), белая карточка FAQ
14px  — кнопки внутри карточки FAQ (десктоп)
16px  — наклонная плашка-подзаголовок (мобильный)
18px  — главная кнопка (десктоп)
20px  — карточка шаблона и «что внутри» (мобильный), карточка преимущества (десктоп)
22px  — тёмный блок CTA (десктоп)
25px  — карточка этапа (мобильный)
28px  — нижняя плашка карточки шаблона (десктоп)
30px  — карточки этапов, «что внутри», шаблонов (десктоп)
36px  — наклонная плашка-подзаголовок (десктоп)
47px  — пилюли фильтров (десктоп)
31px  — пилюли фильтров (мобильный)
```

Обводки: **2px** у карточек на розовом фоне, **1px** у белых карточек,
плашек и кнопок. В макете попадаются 1.695 / 1.795 / 0.897 / 0.441 —
это артефакты масштабирования фрейма, в коде только 1 и 2.

Номерной квадрат этапа наклонён на −3.46°, цифра внутри — на −4.12°.
Углы разные, так в обоих фреймах: цифра стоит чуть менее косо, чем
подложка. Квадрат выступает над карточкой (18px на мобильном, 21px
на десктопе) и заезжает на её верхний край — из-за этого секция
не может обрезать переполнение по вертикали.

Внутренние поля карточки этапа на десктопе в макете разные у всех трёх:
`73/110/68/40`, `73/69/45/40`, `73/113/67/39`. Разброс справа и снизу —
остаток от текстового блока, свёрстанного по содержимому: ширина колонки
375 / 417 / 375. Рабочие значения — верх 73, бока 40, низ 45. Низ взят
как минимум из трёх: столько остаётся под самым длинным текстом, а
высота 261px всё равно держится минимальной. Правое поле в коде равно
левому: в потоке текст переносится сам, фиксировать колонку незачем.

Тени — две, обе почти незаметные, это нормально:
```css
--shadow-card: 0 0 31px 0 rgba(126,126,126,0.05);  /* карточка преимущества */
--shadow-faq:  0 0 31px 0 rgba(0,0,0,0.03);        /* белая карточка FAQ */
```

## Сетка

| | Десктоп | Мобильный |
|---|---|---|
| Ширина макета | 1920 | 390 |
| Боковое поле | 150 | 20 |
| Ширина контента | 1620 | 350 |
| Колонок в сетке карточек | 4 | 1 |
| Шаг между карточками | 20 | 15–25 |

Боковое поле между 1280 и 1920 не прыгает, а растёт линейно: 40px
на 1280 и макетные 150px на 1920. Иначе на 1280 остаётся 980px
контента и десктопная шапка в них не помещается. Тем же правилом
текут расстояния в шапке: от логотипа до первого пункта 40 → 264,
шаг между пунктами 40 → 110. На 1920 всё совпадает с макетом.

## Точки перелома

Нарисованы ровно два состояния: 390 и 1920. Поэтому:

- **База — мобильная.** Вёрстка начинается с 390 и растёт.
- **Десктопная раскладка включается с 1280px.** Контент центрируется,
  максимум 1620px, боковое поле и расстояния в шапке интерполируются
  до 1920, см. «Сетка».
- **Промежуток 768–1279 в макете не нарисован.** Пока туда ставим
  мобильную раскладку с увеличенными полями. Отдельные планшетные
  фреймы — отдельная задача для дизайна.

## Карусели — важное отличие мобильной версии

На мобильном три ряда шире экрана и в макете обрезаны краем фрейма:

1. Пилюли «Признаться в любви / Друг за границей / …»
2. Карточки «Что спрятать внутри» (4 штуки)
3. Карточки «Больше, чем просто открытка» (4 штуки)

Это горизонтальные карусели, прокручиваемые пальцем. Требования:
- `overflow-x: auto`, скроллбар скрыт
- инерционная прокрутка на iOS
- отступ справа равен боковому полю, чтобы последняя карточка
  не липла к краю
- карточка не сжимается: `flex: none`
- виден край следующей карточки — это подсказка, что ряд прокручивается

На десктопе те же ряды помещаются целиком и каруселями не являются.

## Работа с изображениями

Фото пользователя — серый плейсхолдер `--photo` в макете. В реальности
приходит любое изображение, поэтому:

- Текст никогда не лежит на голом фото. Только на подложке.
- Обрезка с учётом лица, не по центру.
- Плейсхолдер до загрузки — сплошной `--photo`, без анимированного скелетона.

## Панель мобильного меню

Бургер в макете нарисован, панель — нет. Спроектирована от токенов:

- панель раскрывается в потоке под шапкой и сдвигает содержимое вниз,
  а не накрывает его. Так не нужен ни оверлей, ни блокировка прокрутки,
  ни ловушка фокуса — экран остаётся одним документом
- ширина во весь экран, поля равны боковому полю сетки
- пункты разделены обводкой 1px цветом `--muted`, высота строки 44
- ниже пунктов — главная кнопка «Создать открытку» во всю ширину
- закрывается по Esc с возвратом фокуса на бургер, по нажатию вне
  шапки и по переходу по ссылке
- у бургера `aria-expanded`, у панели — свой `id`

На десктопе панели нет: с 1280px навигация видна целиком.

## Состояния пилюль

Пилюль на странице два ряда, и они разные. Поводы в FAQ переключают
карточку под собой — это **вкладки**. Фильтры каталога отбирают
карточки в сетке — это **переключатели**. Оформление общее, роль
в разметке разная.

В макете нарисованы только две крайние точки: выбранная пилюля
залита розовым, остальные — обводка и серый текст. Обводка у двух
рядов своя, так в макете, не унифицируем:

| | Поводы FAQ | Фильтры каталога |
|---|---|---|
| Выбранная | заливка `--pink`, текст `--white` | то же |
| Обычная | обводка 1px `--muted`, текст `--muted` | обводка 1px `--ink`, текст `--muted-2` |

Остальное выведено от токенов:

- **Наведение и нажатие на выбранную** — розовый темнеет подмешиванием
  чёрного, 90% и 80%. Ровно та же формула, что у кнопки: одно действие
  выглядит одинаково по всей странице.
- **Наведение на обычную** — заливка `--pink-card`, **и текст темнеет
  до `--ink`**. Второе не украшение, а обязательное: `--muted` на
  `--pink-card` даёт 3.8:1 и не проходит порог 4.5:1. Серый текст
  на розовой заливке оставлять нельзя.
- **Нажатие на обычную** — та же заливка, обводка темнеет до `--ink`.
- **Фокус** — общий из `globals.css`: 2px `--ink`, смещение 2px.
  Отдельного правила пилюлям не нужно.
- **Выключенного состояния у пилюль не бывает.** Повод без карточки
  и фильтр без карточек — это не пустая пилюля, а ошибка данных.

Область нажатия остаётся 44px невидимым полем: сама пилюля 33px.

Выбранная пилюля подтягивается в видимую часть карусели, когда её
выбрали с клавиатуры, — иначе на мобильном фокус уезжает за край
экрана. Плавность прокрутки спрашивается у `matchMedia`, а не берётся
из CSS: правило `scroll-behavior` в `globals.css` до `scrollIntoView`
не дотягивается.

## Доступность

- Контраст `#7a7a7a` на белом даёт 4.6:1 — проходит впритык. Ниже
  этого серого не опускаться.
- Область нажатия минимум 44×44. Мобильные кнопки 45px по высоте —
  проходят. Пилюли фильтров 33px — **не проходят**, нужно добавить
  невидимую зону нажатия сверху и снизу.
- Фокус: обводка 2px цветом `--ink`, смещение 2px. На тёмных блоках — белая.
- Ничего не сообщается только цветом.

## Чего в макете нет и что придётся решать

Список честный, чтобы не наткнуться посреди работы:

- состояния hover, active, focus, disabled у кнопок.
  Секции «Три этапа» это не касается: в ней нет ни одного
  интерактивного элемента, весь текст статичный из словаря
- ~~состояния пилюль~~ — спроектированы от токенов 03.08.2026,
  см. «Состояния пилюль» выше
- ~~раскрытое мобильное меню~~ — спроектировано от токенов 03.08.2026,
  см. «Панель мобильного меню» ниже
- состояния загрузки, ошибки и пустоты
- содержимое карточек шаблонов (сейчас пустые прямоугольники)
- реальные превью в блоке «Больше, чем просто открытка»
- страницы FAQ, «Как это работает», каталог, конструктор
- планшетная раскладка
